## 2. Logic Chain

1. **Relational Schema Design (From Observation 1 & 2)**:
   - Four distinct tables are required to capture the full lifecycle of the health scanner:
     - `scan_sessions`: Captures root session executions with duration, total counts, approval/challenge/rejection counters, and entropy scores.
     - `anomalies`: Captures atomic anomaly instances with foreign key linkage to `scan_sessions(session_id)`, SQL `CHECK` constraints on `detector_type` and `severity`, JSON-serialized `raw_details`, confidence rating, and red-team audit fields (`verdict`, `rationale`, `risk_assessment`, `recommended_action`).
     - `historical_lifelines`: Captures the 5 immutable baseline incident profiles with unique `key` constraints and structured mitigation metadata.
     - `textual_gradients`: Captures behavioral feedback diffs generated by ProTeGi with foreign key linkage to `scan_sessions(session_id)`.
   - Creating composite indexes on `anomalies(session_id)`, `anomalies(detector_type)`, `anomalies(severity)`, `historical_lifelines(key)`, and `textual_gradients(session_id)` ensures query execution times remain < 2ms.

2. **Concurrency & Lock Collision Defense (From Observation 1 & 3)**:
   - Because the Antigravity SDK cron daemon or background subagents may execute concurrently with CLI queries or test runners, standard SQLite default locking causes `sqlite3.OperationalError: database is locked`.
   - Configuring `PRAGMA journal_mode = WAL;`, `PRAGMA synchronous = NORMAL;`, `PRAGMA foreign_keys = ON;`, and `PRAGMA busy_timeout = 5000;` within `get_db_connection()` provides non-blocking concurrent reads and resilient serialized writes.

3. **Idempotent 5-Lifeline Seeding (From Observation 1 & 2)**:
   - The 5 failure lifelines (`ghost_daemons`, `context_rot`, `ecosystem_pollution`, `secret_zero`, `prompt_fatigue`) represent known historical incidents from August 23/24.
   - Using `INSERT INTO historical_lifelines (key, ...) VALUES (...) ON CONFLICT(key) DO UPDATE SET ...` guarantees that calling `init_db()` repeatedly will never produce duplicates or corrupt the baseline, preserving exactly 5 records.

4. **Atomic Transaction Management (From Observation 1, 2, & 5)**:
   - In `log_scan_session()`, inserting a session record, multiple anomaly rows, and textual gradients must occur inside an atomic transaction block (`with conn:`).
   - If an invalid detector type or corrupted payload causes a check constraint failure, the entire session is rolled back, guaranteeing 0 partial or orphaned records.

5. **Loud Assertions Test Architecture (From Observation 5)**:
   - `tests/test_database.py` must isolate every test with its own temporary database file or `:memory:` instance to eliminate shared state.
   - Tests assert exact counts, field equivalences, constraint violation exceptions (`sqlite3.IntegrityError`), JSON roundtrip integrity, and multi-session historical drift calculations.
